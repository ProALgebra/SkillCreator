# Проверка установленного плагина

Дата: 14 ноября 2026 года. Проверка выполнена в пользовательском OpenCode **2.3.0**, через уже работающий локальный background service.

## Установка

- Установленная сборка: `~/.local/share/opencode/skill-curator-runtime/releases/0.2.1-b0438569a32f`.
- Серверная конфигурация: `~/.config/opencode/opencode.jsonc`. Исходная копия сохранена как `opencode.jsonc.skill-curator-backup-20261114T140738Z` рядом с ней.
- Локальная TUI-конфигурация: `~/.config/opencode/cli.json`. Создана для передачи опций менеджеру: server inventory SDK 2.3 передаёт путь пакета без options.
- В обеих конфигурациях подключён один и тот же пакет с `options.local_service_auth: true`. Авторизация выводится из закрытых локальных учётных данных OpenCode; дополнительные секреты на диск не записываются. Npm-зависимости находятся в соседнем runtime/node_modules и доступны сборке версии через стандартное разрешение модулей.
- Сервис перечитал конфигурацию через `opencode reload`. Установленная сборка отделена от исходников, поэтому сборка проекта не заменяет работающий плагин. Каталог версии находится вне node_modules: OpenCode 2.3 кеширует транзитивные импорты внутри node_modules и не заменяет их обычным reload. В каталоге releases подтверждена регистрация watchers для всех модулей плагина.

## Переключатель публикации в 0.2.1

Установлена сборка `0.2.1-b0438569a32f` в server и CLI; `system.health` подтверждает healthy и новую версию. В настоящем сервисе проверены `settings.set_publication_mode`: dry-run без изменения revision, включение mode=auto с обоими разрешениями create/patch, идемпотентный replay и возврат mode=manual. После проверки восстановлена исходная policy: manual, `allow_auto_create=false`, `allow_auto_patch_managed_low_risk=false` (workspace revision 2). Чтобы включить автоматическую публикацию, выберите `/skills-publication` → «Автоматически» либо соответствующий пункт `/skills-settings`.

Итоговые проверки: 102 теста Node, typecheck/build, Bun SQLite, headless OpenTUI с включением/отключением, отменой, no-op, конфликтом/ошибкой, location и JSON-настройками; npm package exports. В настоящем TUI `/skills-publication` найдена через autocomplete и открыла диалог «Публикация навыков» с вариантами «Вручную» и «Автоматически». Переключение не публикует накопленные pending-предложения. Автосоздание, автообновление и возврат к pending проверены полной цепочкой в ядре с контролируемым executor.

## Повторение

Из исходного проекта, с Node.js 22.21.1+:

```bash
npm run test:live
npm run test:live -- --model --provider deepseek --model-id deepseek-flash
```

Вторая команда обращается к настроенному провайдеру. Проверка создаёт только временный навык и архивирует его в `finally`, сохраняя историю аудита. Название модели можно заменить на свою. Для ручной проверки откройте OpenCode в нужном проекте и выполните `/skills-manager`.

- Direct: job `3de2dd0a-70ed-4314-b981-e5087188c560`, completed; создано одно pending-предложение с цитатой и snapshot reference.
- Session: job `ef8cc0e4-26fd-4ac7-97f5-62408c20b214`, completed; кандидат с confidence 0.55 остался без предложения, согласно порогу 0.7.
- Финальная сборка после исправления JSON-цитат: session job `59a6a509-0ab8-4976-adf2-934a89213cb6`, completed; история, preview и модель проверены. Health healthy, `conversation_review.enabled=true`, порог 10, approval manual, `allow_auto_create=false`.
- Использована уже настроенная DeepSeek `deepseek-flash`. Исходные тестовые переписки архивированы, pending-предложения отменены; навыки этой проверкой не публиковались. Незавершённых jobs после проверки нет.
- Автоматический триггер проверен интеграционным тестом настоящего секундного scheduler с SDK double: ошибочный read и успешный edit считаются действиями, анализ не стартует до успешного завершения ответа, внутренние сессии исключены, модель и источники передаются. Генерация автоматической переписки из 10 реальных инструментальных действий в пользовательском сервисе отдельно не выполнялась.

Повторить ручной разбор через SDK:

```bash
npm run test:refine:live -- --provider deepseek --model-id deepseek-flash
npm run test:refine:live -- --mode session
```

Обе команды обращаются к провайдеру и требуют ручного approval в workspace. Модель вправе не находить достаточно надёжного знания; флаг `--require-proposal` дополнительно требует хотя бы одно предложение. Тестовые переписки архивируются, предложения отменяются. Аудит сохраняется.

Автоматические проверки 0.2.0: 94 теста Node, TypeScript/build, Bun native SQLite, headless OpenTUI с обеими ветками выбора location, текущей/исторической `/skills-refine` и отображением ошибок; форматирование и exports извлечённого npm-пакета.
