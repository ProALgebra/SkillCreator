# Проверка установленного плагина

Дата: 14 ноября 2026 года. Проверка выполнена в пользовательском OpenCode **2.3.0**, через уже работающий локальный background service.

## Установка

- Установленная сборка: `~/.local/share/opencode/skill-curator-runtime/releases/0.3.1-a15497222b92`.
- Серверная конфигурация: `~/.config/opencode/opencode.jsonc`. Исходная копия сохранена как `opencode.jsonc.skill-curator-backup-20261114T140738Z` рядом с ней.
- Локальная TUI-конфигурация: `~/.config/opencode/cli.json`. Создана для передачи опций менеджеру: server inventory SDK 2.3 передаёт путь пакета без options.
- В обеих конфигурациях подключён один и тот же пакет с `options.local_service_auth: true`. Авторизация выводится из закрытых локальных учётных данных OpenCode; дополнительные секреты на диск не записываются. Npm-зависимости находятся в соседнем runtime/node_modules и доступны сборке версии через стандартное разрешение модулей.
- Сервис перечитал конфигурацию через `opencode reload`. Установленная сборка отделена от исходников, поэтому сборка проекта не заменяет работающий плагин. Каталог версии находится вне node_modules: OpenCode 2.3 кеширует транзитивные импорты внутри node_modules и не заменяет их обычным reload. В каталоге releases подтверждена регистрация watchers для всех модулей плагина.

## Переключатель публикации в 0.2.1

Установлена сборка `0.2.1-b0438569a32f` в server и CLI; `system.health` подтверждает healthy и новую версию. В настоящем сервисе проверены `settings.set_publication_mode`: dry-run без изменения revision, включение mode=auto с обоими разрешениями create/patch, идемпотентный replay и возврат mode=manual. Чтобы включить автоматическую публикацию, выберите `/skills-publication` → «Автоматически» либо соответствующий пункт `/skills-settings`.

Итоговые проверки: 102 теста Node, typecheck/build, Bun SQLite, headless OpenTUI с включением/отключением, отменой, no-op, конфликтом/ошибкой, location и JSON-настройками; npm package exports. В настоящем TUI `/skills-publication` найдена через autocomplete и открыла диалог «Публикация навыков» с вариантами «Вручную» и «Автоматически». Переключение не публикует накопленные pending-предложения. Автосоздание, автообновление и возврат к pending проверены полной цепочкой в ядре с контролируемым executor.

## Повторение

Из исходного проекта, с Node.js 22.21.1+:

```bash
npm run test:live
npm run test:live -- --model --provider deepseek --model-id deepseek-flash
```

Вторая команда обращается к настроенному провайдеру. Проверка создаёт только временный навык и архивирует его в `finally`, сохраняя историю аудита. Название модели можно заменить на свою. Для ручной проверки откройте OpenCode в нужном проекте и выполните `/skills-manager`.

В headless TUI проверена `/skills-optimize`: запуск с выбранной моделью, предварительный просмотр без запуска модели, отчёты, расписание, пауза/продолжение и подготовка отката. Пункт «Автоматическая проверка» переключает режимы «Выключена», «Проверять устаревание», «Смысловая оптимизация». Расписание и остальные параметры можно изменить отдельно. Разрешение автоматического объединения вынесено в отдельный пункт; для применения нужны одновременно `approval.mode=auto` и `approval.allow_auto_merge=true`.

Базовый `test:live` также прошёл: видимость в native `skill.list`, archive/restore и авторизация.

Живая проверка выполнена через настоящий RPC OpenCode с уже настроенной DeepSeek `deepseek-flash`, в режиме `direct`, при ручной публикации:

- Job `17b240f3-2790-460e-b9e2-cd53d9571622` завершён со статусом `completed`, создано одно предложение объединения двух временных дублирующих навыков.
- Предложение одобрено и применено: создан связный `SKILL.md` короче суммы исходных инструкций; supporting resources сохранены побайтно, оба исходника переведены в `superseded`.
- `curator.rollback` создал отдельное `pending`-предложение. После явного одобрения и применения оба полных исходных пакета восстановлены.
- Отчёт куратора доступен через `curator.status`. Все три временных навыка архивированы после проверки; версии и аудит сохранены.

Финальное состояние сервиса: `system.health` — **0.3.0, healthy, bun:sqlite**; ручная публикация, `allow_auto_merge=false`, `llm_review_enabled=false`, незавершённых jobs нет. Расписание инициализировано, сохранён два отчёта куратора. `format:check` прошёл. Чтобы включить фоновую смысловую проверку, выберите `/skills-optimize` → «Автоматическая проверка» → «Смысловая оптимизация»; политику публикации и разрешение автоматического объединения настройте отдельно.

Фоновый проход с интервалом по умолчанию **168 часов** в пользовательском сервисе не выжидался. Планировщик, сохранение состояния после перезапуска, простой, паузы, бюджет, дедупликация и обработка незавершённых заданий проверены автоматическими тестами. Повторить живую проверку из проекта:

```bash

```

Команда обращается к провайдеру и требует ручного режима публикации. По умолчанию использует `direct`, `deepseek/deepseek-flash`; провайдера и модель можно заменить флагами `--provider` и `--model-id`. Создаёт два временных навыка, проверяет preview, объединение, сохранность ресурсов, одобренный откат и отчёт; временные навыки архивируются в `finally`, аудит сохраняется. Модель вправе оставить навыки без изменений; `--require-merge` требует предложения объединения для успешного завершения этой проверки.

## Выбор навыков и встроенные источники в 0.3.1

Установлена сборка `0.3.1-a15497222b92` в server и CLI, выполнен `opencode reload`. Причина пустого каталога: встроенные навыки OpenCode имеют имена с заглавными буквами, виртуальные пути `skill://` и содержимое без YAML front matter. Discovery больше не проверяет такие API-снимки как создаваемые пакеты: сохраняет очищенный текст для просмотра как readonly/incomplete_source. Полные пакеты по-прежнему требуют строгой проверки; неполные снимки нельзя клонировать, изменять или автоматически оптимизировать.

В живом RPC для `/home/doctor` и каталога проекта подтверждены **Browser, OpenCode, Report**, healthy 0.3.1 и стабильные ревизии при повторной синхронизации. В настоящем native TUI `/skills-manager` показывает три навыка; стрелка вниз выбирает OpenCode, Enter открывает его действия. Поиск `collect standard diagnostics` оставляет Report, первый Enter переводит фокус из поиска к результату, второй открывает `Report · revision 1`. Headless OpenTUI дополнительно проверяет реальные клики мышью, ввод текста, актуальную ревизию после правки, удаление выбранной записи, пустые вкладки, режим viewer и прокрутку длинного каталога.

Прошли **147 тестов Node**, TypeScript/build, Bun native SQLite, headless OpenTUI, format:check и проверка npm-пакета. Базовая живая проверка авторизации и create/visibility/archive/restore также прошла; временный навык архивирован. Для загрузки обновлённой TUI-сборки перезапустите уже открытый клиент OpenCode и снова откройте `/skills-manager`. Выбор: ↑/↓ или мышь, Enter — действия; Ctrl+F/Tab — поиск; Ctrl+R — синхронизация источников.
