# Модель безопасности

## Доверенная граница

Сервер сопоставляет capability-токен с заранее настроенным Principal. `tenant_id` запроса сверяется с этой привязкой; `workspace_id` — с allowlist субъекта. Администратор не получает доступа к другому tenant. Идентификатор сущности не заменяет проверку scope.

| Роль          | Действия                                                                        |
| ------------- | ------------------------------------------------------------------------------- |
| viewer        | Чтение разрешённого каталога, статистики, событий и diff                        |
| editor        | Ручное управление навыками и просмотр                                           |
| curator       | Обучение, ревизии, решения по предложениям, управление jobs и просмотр          |
| administrator | Все действия внутри назначенного tenant/workspace, настройки/policy             |
| worker        | Только lease/heartbeat/complete/fail своего worker_kind и authenticated subject |

Токены читаются из окружения, в БД и логах не сохраняются. Дополнительный локальный режим `local_service_auth: true` выводит capability через HMAC-SHA256 из существующего пароля сервиса OpenCode с отдельным контекстом `opencode-skill-curator/local-capability/v1`. Пароль сервиса не используется как capability напрямую; производный токен остаётся в памяти. Этот режим выключен по умолчанию и предназначен для сервера и TUI одного пользователя ОС.

Локальный режим читает `${XDG_CONFIG_HOME:-~/.config}/opencode/service.json` и требует пароль минимум из 24 символов. Проверяются обычный файл, отсутствие symlink и дополнительных hardlinks; на POSIX также владелец текущего процесса и отсутствие доступа группы/остальных. Ошибка чтения или проверки запрещает загрузку с этим способом авторизации. Плагин не создаёт и не изменяет файл сервиса. Env-токен из `token_env` (по умолчанию `SKILL_CURATOR_TOKEN`) имеет приоритет, поэтому сервер и TUI должны использовать одинаковый способ получения capability. Смена пароля сервиса требует перезагрузки плагина и нового TUI, чтобы оба получили актуальный capability.

Worker token не даёт прав публикации. Lease token относится к конкретному job/attempt и worker. Для удалённых клиентов задавайте отдельные env-токены с нужными Principal bindings; не передавайте им файл локальных учётных данных сервиса. Используйте TLS, защищённый reverse proxy и аутентификацию OpenCode на удалённом сервере; capability дополняет защиту транспорта.

SDK 2.3 не передаёт пользователю plugin RPC проверенную идентичность вызывающего. Поэтому TUI также передаёт capability. Нельзя считать весь удалённый OpenCode-сервер единственным доверенным локальным пользователем. Общий live event stream SDK не фильтруется по capability: приватные события через него намеренно не транслируются. `events.replay` проходит обычную авторизацию и возвращает только разрешённый scope.

## Файлы

Запись выполняется только в выбранный корень управляемой библиотеки, в каталоги с вычисленными именами. Проверяются компоненты пути, нормализация, realpath разрешённых источников, symlinks, число hardlinks и тип файла. Абсолютные пути, `..`, конфликт file/directory и ссылки на отсутствующие локальные зависимости отклоняются. Внешние источники readonly; перед обслуживанием их полная копия создаётся в управляемой библиотеке.

Бинарные файлы сохраняются побайтно через base64 envelope. Никакие скрипты из пакетов не исполняются. Слияние сохраняет каждое исходное дерево отдельно; изменение смысла относительного cwd скрипта требует ручной оценки diff.

Защита рассчитана на приложение с доверенным владельцем локального data directory. Враждебный процесс с теми же правами ОС может подменять файлы между lstat и rename; от этого требуется отдельная изоляция ОС. Каталог данных должен принадлежать только пользователю сервиса, без совместной записи другими арендаторами.

## История и LLM

Секреты, токены, Bearer/cookie/password, JWT, private keys, email, часть телефонов и private home paths маскируются до хранения транскрипта. Перед публикацией применяется тот же фильтр к файлам, перед передачей модели — дополнительная очистка. Детектор эвристический: он не доказывает отсутствие всех возможных PII или неизвестных форматов секретов. Владельцы должны просматривать diff, особенно при импорте собственной истории.

Source refs и metadata с обнаруженными секретами отклоняются. Raw transcripts не сохраняются в jobs; payload материализуется при dispatch. По умолчанию внешнему исполнителю не передаётся текст истории. Встроенная служебная сессия создаётся с deny-all permissions. Все режимы возвращают декларативные предложения; сервер проверяет scope, revisions, policy, ссылки, секреты и структуру ответа.

## Approval и восстановление

`settings.set_publication_mode` доступен только administrator в разрешённом scope, с проверкой revision и idempotency. Он атомарно переключает mode и разрешения create/patch; настройки архива, privacy и защиты ручных навыков сохраняются. TUI `/skills-publication` вызывает эту же ручку. По умолчанию режим остаётся manual.

`safe` и `manual` не публикуют предложения автоматически. Для auto patch нужны одновременно `approval.mode=auto`, отдельный allow-флаг, managed навыки, low-risk patch и отсутствие блокировки. Auto archive требует отдельного флага, положительных наблюдений использования, срока и отсутствия pin/lock. Новые навыки публикуются автоматически только при одновременном `approval.mode=auto` и `allow_auto_create=true`; по умолчанию этот флаг выключен. Merge и split остаются на ручном approval. Автор автоматического approval — `system.policy`, он фиксируется в аудите.

Разбор переписки — отдельный путь от verified-only Learner. Снимок хранится с `verified:false`, а кандидат помечается `evidence_kind:conversation_snapshot`. Модель видит недоверенные данные и возвращает только декларативные кандидаты. Проверяются буквальные цитаты, неизменяемый ID снимка, список допустимых целей и зафиксированные revision/hash. Наличие цитаты не доказывает истинность вывода. При включённой автопубликации модельные ошибки могут попасть в библиотеку; исходный ручной режим оставляет оценку владельцу.

SDK-адаптер сверяет directory каждой переписки с выбранным проектом, запрещает внутренние сессии, чтение во время ответа и изменения истории в процессе захвата. Передача контекста external/VALERIA требует `privacy.send_raw_transcripts_to_external=true`. Пользовательское разрешение на такую передачу не выводится из содержимого переписки.

Невалидный вывод модели, конфликт revision/hash, неизвестный исход executor, повреждённая БД или недоступные файлы блокируют соответствующую публикацию. Перезапуск не вызывает повторный LLM-run после неизвестного исхода. Резервные копии содержат приватные очищенные данные и требуют такого же ограничения доступа.
